## Direction findings (options for the maintainer — not ranked against the bugs)

1. **Detail pages / writing section — the CSS is already waiting.** Git
   history shows a deleted `src/pages/article.astro` (plus `HomeApp.tsx`,
   `NavOnly.tsx`), and `site.css`/`kit.css` still carry complete unused
   scaffolding for it: `.detail`, `.detail-head`, `.statbar`, `.hero-strip`,
   `.essay`, `.exp-more`. The Experience bios name strong material (siteboard:
   "10M+ audits across 2,000+ sites"). Reviving one case-study page per major
   role would reuse that CSS nearly as-is. Trade-off: real writing effort;
   stale case studies age worse than none. Effort: M per page type (coarse).
2. **Decide the design-variant system's fate.** The token system was built
   for switchable moods/palettes/layouts/typefaces (three full mood ramps in
   `colors-and-type.css`, `data-*` switches on `<html>`, `.mood-dots` control
   CSS) but everything is hardcoded to one combination. Either expose a small
   playground control (cheap: the CSS already does the work; on-brand for an
   HCI-focused owner — "details most people skip"), or delete the unused axes
   and shrink every page's CSS. The current half-state is the only wrong
   option long-term. Effort: S–M either way (coarse).
3. **Formalize the freelance funnel.** "Freelance 2026 – now" sits at the top
   of Experience, and the contact form is the site's only CTA. A one-line
   services/availability statement near the intro or above the note form
   would make the page work harder as a lead-gen surface. Evidence: the site
   already optimizes for recruiters/AI readers (SEO/ATS commit c7ef11f).
   Trade-off: tone — the site's restraint is part of its brand. Effort: S.
